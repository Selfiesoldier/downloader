# Plan 01.03: Single-Worker FIFO Queue & Interactive Cancellation

<objective>
Protect Android Termux low-resource environments (RAM < 150MB, bounded CPU/disk) by introducing a strict single-worker FIFO download queue (`asyncio.Queue`, `max_concurrency=1`), live queue position tickets, and interactive cancellation (`/cancel` and inline button) with immediate child process/worker termination and temp directory purge.

Purpose: Prevent device freezing, out-of-memory crashes, and disk thrashing on mobile Termux devices caused by concurrent downloads, while giving users full control to cancel downloads at any time.
Output: `queue_manager.py`, updated `bot.py`, and `tests/test_queue_manager.py`.
</objective>

<task type="auto">
  <name>Implement DownloadQueueManager and Process Supervisor in queue_manager.py</name>
  <files>queue_manager.py</files>
  <action>
    Create queue_manager.py with:
    1. DownloadJob Dataclass:
       - Fields: job_id (str), chat_id (int), user_id (int), message_id (int), url (str), mode (str), title (str), status (str: "queued", "active", "cancelled", "completed", "failed"), temp_dir (str), cancel_event (asyncio.Event), process (subprocess or task handle), created_at (float).
    2. DownloadQueueManager Class (Singleton):
       - Internal FIFO queue using asyncio.Queue().
       - Strict concurrency: worker loop that processes exactly 1 active job at a time (max_concurrency=1 for Termux).
       - Active job registry and waiting list tracking to compute dynamic queue position: get_queue_position(job_id) -> int.
       - register_process(job_id, proc) to link active subprocess / pid.
    3. Cancellation Engine (cancel_job):
       - If job is in queue: marks status as "cancelled", removes from waiting list, and notifies user.
       - If job is currently active: sets cancel_event, sends SIGTERM to child process/thread, waits up to 2.0s, and escalates to SIGKILL if still alive.
       - Cleans up job's temp_dir immediately to free disk space.
    4. Worker Loop:
       - Continually awaits items from asyncio.Queue.
       - Checks cancel_event before and during execution.
       - Automatically advances to the next queued job on completion, failure, or cancellation.
    AVOID: Unbounded thread pools or creating multiple concurrent workers on mobile devices.
    AVOID: Leaving orphaned temp directories when a task is cancelled mid-download.
  </action>
  <verify>python -c "import queue_manager; q = queue_manager.DownloadQueueManager(); assert q.max_concurrency == 1; print('DownloadQueueManager initialized successfully')"</verify>
  <done>DownloadQueueManager enforces single-worker FIFO execution and clean process termination on cancellation.</done>
</task>
