# Plan 01.02: Parallel Segmented Chunk Downloader & Socket Acceleration

<objective>
Saturate network bandwidth (up to 40 Mbps) for both progressive media and multi-fragment streams via parallel multi-chunk byte-range HTTP streams (4-8 concurrent pipes) with chunk ID indexing, zero-loss byte reassembly, yt-dlp `concurrent_fragment_downloads: 8`, and native `aria2c` auto-detection.

Purpose: Prevent bandwidth underutilization on high-speed mobile and broadband connections, slashing media download times while guaranteeing byte-level integrity during reassembly.
Output: `chunk_downloader.py` and `tests/test_chunk_downloader.py`.
</objective>

<task type="auto">
  <name>Implement SegmentedChunkDownloader and byte-range assembler in chunk_downloader.py</name>
  <files>chunk_downloader.py</files>
  <action>
    Create chunk_downloader.py containing:
    1. SegmentedChunkDownloader class:
       - Uses aiohttp or httpx async client to inspect headers via HEAD request (Content-Length, Accept-Ranges: bytes).
       - Splits target file size into N segments (default 4 to 8 concurrent streams, clamped to min 1MB per chunk).
       - Issues concurrent GET requests with Range: bytes={start}-{end} headers.
       - Writes parts into isolated directory using indexed chunk names: chunk_00.part, chunk_01.part, etc.
       - Provides progress callback reporting aggregate bytes downloaded across all active range streams.
    2. Zero-Loss Reassembler (reassemble_chunks):
       - Verifies every chunk index exists on disk and individual chunk size matches expected byte range.
       - Concatenates chunk parts sequentially in index order into destination file using buffered binary streams (e.g., 64KB copy chunks).
       - Verifies total reassembled file size matches expected Content-Length exactly.
       - Purges temporary chunk parts immediately after verified reassembly.
       - Rolls back and raises exception if any chunk is missing or corrupt.
    AVOID: Loading whole files into RAM; always stream chunks directly to disk parts to stay within Android Termux 150MB RAM ceiling.
  </action>
  <verify>python -c "import chunk_downloader; assert hasattr(chunk_downloader, 'SegmentedChunkDownloader'); print('SegmentedChunkDownloader imported successfully')"</verify>
  <done>SegmentedChunkDownloader supports concurrent byte-range streams and zero-loss sequential chunk assembly.</done>
</task>

<task type="auto">
  <name>Implement aria2c auto-detection and turbo yt-dlp fragment options</name>
  <files>chunk_downloader.py</files>
  <action>
    Add socket acceleration helpers to chunk_downloader.py:
    1. detect_aria2c() -> str | None:
       - Checks Termux binary path (/data/data/com.termux/files/usr/bin/aria2c).
       - Checks system PATH via shutil.which("aria2c").
       - Checks local bin directory (bin/aria2c or bin/aria2c.exe).
       - Returns verified executable path or None.
    2. get_turbo_downloader_opts(base_opts=None, concurrency=8) -> dict:
       - Configures concurrent_fragment_downloads: concurrency (default 8).
       - Configures buffersize: 1048576 (1MB) and http_chunk_size: 10485760 (10MB).
       - Configures retries: 5 and fragment_retries: 5.
       - If aria2c is detected, injects:
         external_downloader: {"default": aria2c_path},
         external_downloader_args: {"aria2c": ["-s", str(concurrency), "-x", str(concurrency), "-k", "1M", "-j", str(concurrency), "--file-allocation=none", "--summary-interval=0"]}
    3. download_media_turbo(url, mode, temp_dir, ydl_opts=None):
       - Wrapper combining turbo downloader options with ytdl or segmented direct downloader.
    AVOID: Using --file-allocation=falloc on mobile Termux file systems as it can cause permission errors or hanging on Android. Use --file-allocation=none.
  </action>
