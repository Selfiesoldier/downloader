# Plan 01.04: Pipelined Streaming MTProto Upload & Resource Guard

<objective>
Slash total turnaround wait time in half by streaming 512KB chunks to Telegram via `SaveBigFilePartRequest` concurrently while media downloads, multiplex uploads across parallel MTProto TCP connections to target Telegram Data Centers, protect Termux storage via a 500MB disk headroom guard, and purge orphaned temp files on startup and post-download.

Purpose: Prevent cellular bandwidth bottlenecks during Telegram uploads while strictly protecting low-storage mobile devices from running out of disk space.
Output: Enhanced `fast_telethon.py`, `resource_guard.py`, and `tests/test_resource_guard.py`.
</objective>

  <name>Implement Multi-Socket MTProto DC Pooling and Pipelined Streaming in fast_telethon.py</name>
  <files>fast_telethon.py</files>
  <action>
    Enhance fast_telethon.py with socket acceleration and pipelined streaming:
    1. MTProtoConnectionPool:
       - Manages a pool of parallel MTProto client sender connections (default 4-8 connections) targeting the user's specific Telegram Data Center (DC).
       - Bypasses Telegram's single-socket ~1.5–2 MB/s throttling by distributing RPC requests across the connection pool to achieve 15–30 MB/s throughput.
    2. PipelinedStreamUploader:
       - Accepts a readable byte stream or chunk generator as media downloads to disk.
       - As soon as each 512 KB boundary is reached, immediately dispatches SaveBigFilePartRequest with part_idx via the connection pool without waiting for the full download to complete.
       - Tracks uploaded parts and generates final InputFileBig(file_id, part_count, file_name) once the stream closes.
    3. Backwards Compatibility:
       - Update existing fast_upload_file(client, file_path, progress_callback, concurrency=8) to use the connection pool for uploaded files, keeping existing call signatures functional.
    AVOID: Exceeding 512 KB part size as MTProto hard-rejects larger part sizes with PartSizeInvalidError.
    AVOID: Creating unbounded new socket connections that could trigger Telegram FloodWaitError.
  </action>
  <verify>python -c "import fast_telethon; assert hasattr(fast_telethon, 'fast_upload_file'); print('fast_telethon.py multi-socket interface verified')"</verify>
  <done>fast_telethon.py supports multi-socket MTProto connection pooling and pipelined 512KB streaming uploads.</done>
</task>

<task type="auto">
  <name>Implement DiskHeadroomGuard, OrphanCleaner, and SmartQualityBadges in resource_guard.py</name>
  <files>resource_guard.py</files>
  <action>
    Create resource_guard.py with:
    1. DiskHeadroomGuard:
       - check_disk_headroom(target_dir: str, estimated_bytes: int = 0, min_headroom_mb: int = 500) -> tuple[bool, str]:
         - Inspects free storage using shutil.disk_usage(target_dir).free.
         - Requires minimum free space of max(500 MB, 1.5 * estimated_bytes).
         - Returns (True, "") if storage is sufficient, or (False, advisory_message) advising the user to free up device storage.
    2. OrphanCleaner:
       - clean_orphaned_temp_dirs(base_dir: str, max_age_seconds: int = 3600) -> list[str]:
         - Scans base_dir and system temp for directories starting with "dl_".
         - Recursively searches for stale .part, .ytdl, and .temp files older than max_age_seconds (or all inactive folders on bot startup).
         - Safely removes stale files and directories while ignoring active sessions, cookies, or .env files.
         - Returns list of purged directory paths.
    3. SmartQualityBadges:
       - format_quality_badge(height: int, file_size_bytes: int = 0, is_audio: bool = False) -> str:
         - Produces clear, bandwidth-aware labels:
           - 720p: "⚡ Fast 720p (~30MB)"
           - 1080p: "🎬 Full 1080p (~150MB)"
           - 480p / 360p: "💾 Data Saver 480p (~15MB)"
           - Audio: "🎵 Audio (MP3) (~8MB)"
    AVOID: Deleting files in cookies/ or session files (bot_mtproto.session) during orphan cleanup.
  </action>
  <verify>python -c "import resource_guard; ok, _ = resource_guard.check_disk_headroom('.', 1024); assert ok; print('resource_guard.py initialized successfully')"</verify>
  <done>resource_guard.py provides 500MB disk headroom verification, automated orphan cleanup, and smart quality badges.</done>
</task>
